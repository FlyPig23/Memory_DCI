# Retrieval for agents：可借鉴的机制与迁移边界

核查日期：2026-09-08。本文是定向文献调研，优先看作者论文与官方仓库。除单独的 DCI-Agent-Lite / DR-DCI 源码报告外，其余工作以注明的论文阅读深度为准，未逐仓库复现，也没有运行实验。

**最值得先借鉴的是 SIEVE 的“条件筛选—候选检查—定点读取”和 IRCoT 的“围绕未解决问题继续查询”。** ITER 提醒我们区分候选出现、被读和实际有用；ExpeL 与 ReasoningBank 则是后续经验表示对照的依据。完整建议已写入[原框架第13节](../../../reports/DCI_upgrade_report.md)。

## 1. 搜索接口、候选和读取

| 工作；本次阅读 | 论文机制 | 对本项目的启发 | 不能直接推断什么 |
|---|---|---|---|
| **SIEVE**，2026；v3 §3、附录B/C及官方仓库说明 | 字段 Boolean 条件决定候选资格，独立 ranker 排序；卡片显示结构和命中片段，fetch 读取指定章节。零命中时按约束覆盖率及词法检索恢复 | 把 action、tool、observation、error 等已有结构保留到搜索和阅读接口；显示满足/放宽的条件，阅读命中所属事件 | 网页章节不等于轨迹事件。其 DCI 对照提示与步数有偏差，不能拿成绩证明对我们的实现必然更好。详细来源：[论文](https://arxiv.org/html/2608.02751v3)、[官方代码](https://github.com/ielab/skim-search-agent) |
| **RISE**，2026；论文摘要、官方 README | BM25 构建有限工作区，agent 在其中用终端检索；完整方法再提供可导航的文档目录 | 分别控制“候选边界”和“候选内部导航”，作为未来规模实验对照 | 未在本次逐文件核查 RISE。小库命中质量问题未必由缩小候选解决。来源：[论文](https://arxiv.org/abs/2606.06880)、[官方代码](https://github.com/texttron/RISE) |
| **GrepSeek**，2026；v1摘要与方法概览 | 通过 Tutor/Planner 生成搜索训练轨迹，再训练执行 shell 查询的搜索 agent | 原语存在不等于搜索策略强；可先讨论构建集内的少量搜索示例 | 只加提示词不是 GrepSeek 训练复现；训练中使用答案的角色不能移入测试。来源：[论文](https://arxiv.org/html/2605.29307v1) |

SIEVE 的特别注意点：其 Boolean 约束在非空候选时保持；零命中回退另有排序路径，不能将整个系统说成纯严格 Boolean。候选卡片只帮助选择读取位置，不保证任何历史方法在当前环境适用。该论文附录 C.1 承认其 DCI 对照省去五步搜索提示、采用100步而非原论文300轮。我们另查 Lite 发现五步位于 IR prompt，而非所有默认 prompt。应引用其具体受控比较，不说“严格复现 DCI 后已证实全面更好”。

## 2. 查询状态、检索时机和候选新颖性

| 工作；本次阅读 | 论文机制 | 对本项目的启发 | 适配限制 |
|---|---|---|---|
| **IRCoT**，ACL 2023；ACL摘要与方法概述 | 检索和逐步推理交替，中间推理帮助下一次检索 | 显式记录子目标、已知事实和方法缺口，再决定查什么 | 使用简短可观察状态是适配，不要求私有思维链。来源：[ACL论文页](https://aclanthology.org/2023.acl-long.557/) |
| **FLARE**，EMNLP 2023；ACL摘要与方法概述 | 根据下一句预测形成检索查询，在低置信词处检索并重新生成 | 查询应发生在有实际不确定性时 | 当前框架没有已验证的逐token置信触发接口；工具错误/验证失败是替代设计，不是原算法等价实现。来源：[ACL论文页](https://aclanthology.org/2023.emnlp-main.495/) |
| **Agentic-R**，2026；v1 §4及查询表示讨论 | 以局部 query–passage 相关性和继续求解后的答案正确性构造检索训练信号 | 对候选标注“能否推进当前操作”，而不只看题材相似 | 全局收益监督涉及训练答案与额外续跑；本次仅提出评估思路，未训练或续跑。来源：[论文](https://arxiv.org/html/2601.11888v1) |
| **AgentIR**，2026；论文摘要、官方项目/仓库说明 | 查询编码加入 agent 搜索前的 reasoning | 短 search brief 可以表达操作目的，减少裸 query 的歧义 | 本次未逐文件审查；外部简述不等于论文所用 reasoning。来源：[论文](https://arxiv.org/abs/2603.04384)、[作者项目](https://texttron.github.io/AgentIR/) |
| **ITER**，2026；v1 §3–4、§7.1 | 根据主问题、当前和先前 query 编码；用访问记录构造不同负例，减少已读重复证据 | 把已返回未读、已读有用、已读无用分开；旧候选保留读取入口 | 训练中的去重采集接口与最终统一检索评测要区分；简单列表去重不等于训练后的 ITER。来源：[论文](https://arxiv.org/html/2608.27912v1) |

**需要保留的分歧：**Agentic-R 采用 `Q + q` 并报告先前 query 的噪声；ITER 的设置中 `Q + q + 先前query` 更稳健，反而加入已访问全文/解释会降低召回。这个差异可能来自训练、模型和任务，不能直接判定哪种在 WildClawBench 上最好。可比较短 query、主问题+query、再加有界历史；不要默认把全部轨迹塞进检索器。

**关于候选“有用”：**Agentic-R 的最终答案监督、ITER 的访问后相关性判断，都是特定训练标签。对历史经验，方法曾经成功、模型说有用、当前确实采用、采用后通过验证是不同事实。未读候选也只是未知，不能直接作为可靠负例。

## 3. 从经验中形成策略

| 工作；本次阅读 | 论文机制 | 可讨论方向 | 与首轮设定的区别 |
|---|---|---|---|
| **ExpeL**，2023起；v3 §4.1–4.3 | 构建阶段收集成功/失败；比较经验提取并修订 insights；推理时按任务相似性检索成功轨迹，配合 insights | 在构建集提炼操作前提和失败警示，保留原轨迹引用；比较示例、策略及两者结合 | 不是动态全文 DCI；成功示例检索与 insights 是两个部件。来源：[论文](https://arxiv.org/html/2308.10144v3)、[官方代码入口](https://github.com/LeapLabTHU/ExpeL) |
| **ReasoningBank**，2025起；v2 §3.2–3.3 | 从自评成功/失败中提炼 title/description/content 记忆，以 embedding 检索，并把后续经验继续写回；另研究 MaTTS | 为 A4 的策略卡和反例设计提供依据，尤其关注失败条件 | 原文是持续 test-time 学习；本项目若保持冻结测试，只能在构建集提炼并冻结，不能照搬跨测试写回。来源：[论文](https://arxiv.org/html/2509.25140v2) |

策略抽象可能降低噪声，也可能抹掉重要前提或把一次成功归纳成错误规则。建议卡片保留来源动作/观察、已验证和未知条件，并允许回到原文。确定性事件导航属于可逆接口；LLM 写出的“通用方法”已经改变表示，需要算作单独的 A4 因素。

## 4. 取舍与讨论顺序

1. 先明确多词匹配语义、可搜索字段、hit 到原事件的定位和续读行为。候选排序、字段去噪和展示去重分别记录，不将组合收益全归因于关键词。
2. 再定义简短搜索状态、适用性检查、采用/拒绝记录，以及由真实阻塞或证据缺口引出的再查。
3. 若定位改善而执行仍无收益，检查库内是否存在可迁移经验、执行器是否能转化，以及评分是否对应实际产物；不能只扩大搜索次数。
4. 将学习型 reranker、经验蒸馏、动态 pull 和在线更新列为不同后续方向。新方法选择和参数需要新的冻结方案；本次不启动这些工作。

后续评估应从命中、读取完整性、适用性、采用验证一直跟踪到任务分数及成本。已分析的24题只能作为诊断/回归集；构建集内部验证也须按 family 排除全部模型轨迹及其派生记忆。主框架第13.6节给出了这些验证条件。

**证据强度说明：**本文没有声称已系统检索所有相关文章，没有跨论文直接比较分数，也没有将问答文档证据的结论等同于历史经验迁移。最新预印本值得提出假设；是否适合本项目仍需受控验证。来源清单见 [literature_sources.json](literature_sources.json)。
